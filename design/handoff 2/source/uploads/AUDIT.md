### 1.6 Auto tracking: what actually exists

**There is no auto-posting.** Nothing turns a due date into an expense:
- `recurringExpenses` is written by subscription actions and synced, but no code reads it (grep: only store, mappers, sync, hydrate). It is a dormant mirror; it does not feed stats, budget, Flow, or cron.
- `/api/cron/notifications` only evaluates recurring *debt* payments and month-end; no renewal reminders. `vercel.json` crons: notifications 06:00, prices 03:00.
- Charges become expenses only via SMS (below) or a manually entered expense, and the manual expense form has no subscription link, so only SMS can set `linked_subscription_id`.
- Consequence: because nothing auto-posts, there is no auto-post vs SMS duplicate risk today. If auto-posting is ever added it must dedupe against `linked_subscription_id` + `cycleWindow`.

### 1.7 SMS tracking path

1. `/api/sms/parse` (`app/api/sms/parse/route.ts`, tx.outcome `'subscription'` at :1079 sends the push `smsSubscriptionTitle/Body`) and `/api/sms/confirm` share `dispatch.ts`.
2. `dispatch.ts:~518-560`: only `purchase` / `online_purchase` call `matchSubscription`; a hit sets `linkedSubscriptionId` and forces `categoryOverride:'Subscription'`; if the hit carries `planChange` it parks `pending_plan_id` + `pending_amount` on the row (only when nothing is pending).
3. `matchSubscription.ts`: merchant -> brandKey (`normalized` then raw) -> candidate subs of the user for that brand (status active|trial, not deleted) -> per candidate: amount in SUB currency within +-5% (FX via `tryConvertCurrency`; no FX path = "unverifiable", never preferred over a verified one) or detected plan change -> date gate (charge day within 5 days of billing day, short way round the month, month-end clamped; skipped for weekly) -> first hit wins.
4. `createSmsExpense.ts:314` writes `expenses.linked_subscription_id`. `merchantNormalizer.ts` renames purchase merchants to the catalog brand name; `merchantCategoryCache.ts` seeds categories from the catalog default.
5. Client: realtime/FCM -> `AppShell.tsx addExpenseIfMissing` (now also pulls the linked subscription, see B13).
6. Discovery of untracked subs: `useSubscriptionDetector` (sms_parse_log, 90-day lookback) -> `detectRecurringCharges` -> `SmsSubscriptionDetectionBanner` -> `openAddSubscriptionWithPrefill` -> add sheet seeded with the charged amount/currency/day.

### 1.8 Budget and reporting links

- `useSubscriptionsMonthlyTotal.ts` -> `subscriptionsMonthlyBaseTotal`: active + trial, monthly-equivalent, converted to base. Used by the page header total and `BudgetCommittedCard`.
- `BudgetCommittedCard.tsx`: count, total, next renewal; link only (display, not subtracted from any budget).
- Actual spend: subscription charges are normal expenses with category `Subscription` (`finance.ts:32`, `categoryGrid.ts:65`, chip `categoryChip.ts:29`). `Subscription` is a spend category (not in `NON_SPEND_CATEGORIES`), so Flow ledger, net worth/cashflow accrual, reports and `useMonthlyStats` include it. It rolls up into a legacy `Enjoyment` row only if the plan has no dedicated Subscription row (`CATEGORY_BUDGET_ALIASES`, `categoryMeta.ts:44`).
- Budget planner preset row is labelled `Subscriptions` (`budgetPlannerPresets.ts:15`) (see B12).
- Subscriptions and `recurringExpenses` are NOT in `useMonthlyStats`, so there is no double counting between the planner mirror and Flow; the cost is that unpaid/unlinked subscriptions are invisible to actuals (O1).
- Buddgy: `runLookup kind:'subscriptions'` (`lib/ai/buddgyLookup.ts:34`); `buddgyIdeas` maps `/subscriptions` to the expenses idea set.

## 2. Behaviour spec (intended) and deviations

### 2.1 State machine

```
            add (catalog/custom/prefill)
 (none) ───────────────────────────────────► active ◄──────────────┐
                                              │  ▲                  │ reactivate
                                  cancel      │  │ (edit keeps      │ (clears cancelledAt,
                              (confirm dialog)│  │  status)         │  recomputes next date,
                                              ▼  │                  │  reactivates recurring row)
                                          cancelled ────────────────┘
  delete (confirm) from ANY state ──► removed (sub + recurring row; expenses keep history)
  trial / paused: valid enum values, rendered, counted (trial yes, paused no) but UNREACHABLE from the UI (see O2)
  pendingPlanId: orthogonal flag on an ACTIVE sub. set by SMS dispatch; cleared by apply / dismiss / cancel / an edit that changes plan or price
```

| Status | Counted in monthly total / Committed | Recurring row `isActive` | Matched by SMS | Card section |
|---|---|---|---|---|
| active | yes | true | yes | Active |
| trial | yes (arguably should not until converted, O11) | true | yes (new) | Active, "Free trial" badge |
| paused | no | false | no | Active, "Paused" badge |
| cancelled | no | false | no | Cancelled, dimmed, "Cancelled <date>" |

### 2.2 Billing cycles

- Monthly/quarterly/yearly are anchored on `startDate` + `billingDay`; each hop adds N months then re-applies `billingDay` clamped to the month (Jan 31 -> Feb 28 -> Mar 31; Feb 29 yearly -> Feb 28 -> Feb 29 in leap years).
- Weekly steps 7 days from `startDate`; `billingDay` is ignored for scheduling.
- Next date is derived, never trusted from storage (`upcomingBillingDate`). "Paid this cycle" is derived from linked expenses in `cycleWindow`; a charge on the next billing date opens the next cycle; refunded/declined charges do not count.
- Local-calendar arithmetic (date-fns) so DST does not shift days (tested in Cairo, New York, Auckland, Dubai).
- Form derives `startDate` from billingDay (this month, or last month if the day has not come). The first-payment date and, for quarterly/yearly, the renewal month are not captured (O3).

### 2.3 Currency

A sub is stored in ONE currency (USD-billed services can be stored in USD or in the local currency converted at add time). Totals convert each sub to the base currency at current rates (`convertCurrency`, falls back to unconverted amount with a console error if no FX path). SMS matching converts the charge into the SUB currency and compares +-5%.

### 2.4 Plan change

Detected only from a tracked SMS charge that lands on a DIFFERENT catalog plan of the same brand/region/currency. Never auto-applied. Apply = adopt plan id + label + the charged amount; effective immediately (no effective date, no proration, no history). A price that matches no plan (promo, proration, price rise) is silent.

### 2.5 Deviations (summary; details in section 3/4)

No auto-posting (O1); statuses trial/paused unreachable (O2); stored `nextBillingDate` stale (fixed, B2); edit re-anchored schedule (fixed, B3); offline edits lost (fixed, B1); weekly/trial/Arabic never matched (fixed, B6-B8); plan-change prompt delayed to next cold start (fixed, B13).

### 6.6 Redesign observations

Missing states worth designing: trial (with end date), paused, shared/family, price-changed, overdue/"expected but not seen", first-payment date, reminders, per-subscription history (the linked expenses already exist), cancel flow with the unused `cancelHint`, annual-equivalent toggle, category chooser, empty "paid" explanation, and a visible auto/manual tracking indicator (O1).
