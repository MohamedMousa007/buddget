# QA round 2 - live UI/UX exploration (partial)

Env: next dev --webpack, port 3001, dev auth bypass, no Supabase. Seeded via window.__finance (28 expenses in 9 categories, EGP/USD/AED, one 98.7M outlier, 2 debts, 1 savings pocket 50k, 1 goal; 2 income sources are the bypass default). Browser pane stayed "hidden" so only screenshot-light checks were possible; every audit was via javascript_tool (touch targets, accessible names, h-scroll, contrast).
COVERAGE: 375 light (main), 375 Arabic (settings, 404, legal, offline, start), 375 dark (flow), 768 dark (flow), 1280 dark (flow). Other route x viewport x theme x language combinations NOT done. No add/edit/delete flow beyond the Add-expense sheet (opened, Escape-dismissed, save disabled with hint when empty).

ENVIRONMENT BLOCKERS (not app bugs, but they limited coverage)
- Dev server restarts ("approaching used memory threshold") every few minutes; every cold route compile took 1-5 min (flow 133s, wealth 328s); the first page load after a restart threw ChunkLoadError app/layout.js and showed the global error screen ("Buddget hit a problem") until reload. Several page loads showed the Flow skeleton for 7-20 s before the real route rendered.
- A production build would avoid this; not used because the brief was read-only.

FINDINGS
X1 P2 Flow hero, 375 light/dark, en: big number collides with the per-day figure. Steps: seed a 98.7M expense, open /flow at 375. Observed: "99,000,800.79" (font ~44px) overlaps the "3,666,696/day" figure (the leading "3," is covered; visible "666,696/day"), and the MONEY OUT cell shows "-99,000,..." truncated. Expected: number scales down or wraps, no overlap. Evidence: screenshot at 375x812. Fix: use a fit-text/clamp step on HeroBand for >10 digits, give the per-day block min-width and let the number shrink.
X2 P2 Reports "Total money in" 62,240 vs Flow "Money in" +8,240 vs Paydays "0 of 54,000 EGP received". Same month, same data. Reports counts un-received recurring income as "earned" (caption says so) while Flow/Paydays count only received. Also Reports shows net worth "E£ -111,390.29" while other screens use "EGP" / bare numbers. Expected one definition of "money in" (or an explicit "expected vs received" label) and one currency format. Fix: label Reports figure "Expected" or switch to received, unify formatter.
X3 P3 Reports (375): large amounts wrap with the currency symbol stranded on its own line ("E£" / "99,000,800.79", "E£" / "-98,938,560.79"). Fix: nowrap + shrink or put the symbol inline-flex with the number.
X4 P2 Unnamed link on every authenticated page: header logo `<a class="shrink-0">` 101x24 (also on legal pages `a.flex items-center gap-2`). No aria-label/text. Count: 1 unnamed control per page on flow, savings/wealth, goals, debts, reports, accounts, subscriptions, notifications, budget-setup, settings, 404, legal. Also 24px high (<44). Matches the plan's "2 unnamed on /flow" in part (now 1 in the audit). Fix: aria-label="Buddget home" and a 44px min hit area.
X5 P3 (ongoing) Touch targets <44px, measured at 375: /flow 25 (Budget 36x36, Profile menu 36x36, Set budget 86x26, month arrows 32x32, All/In/Out 110x36, Open filters 88x36, category chips 77x36); /wealth 6 (Emergency fund chip 87x28, Refresh prices 32x32, Show world prices 32x32); /goals 6 (filter tabs 88x36); /debts 8 (Edit debt 32x32, carousel dots "Go to 1" 18x8 and "Go to 2" 8x8); /reports 11 (range chips 101-156x40); /accounts 4 (Hide balances 32x32); Add-expense sheet: Today 84x36, Add note 96x28; legal pages 16 inline links (Terms 33x16, Privacy 39x16, mailto 141x21). /paydays, /budget-history, /offline, /profile switches (44x24 track inside a >=56px row) pass. Header Budget and Profile 36x36 repeat on every page: single fix covers ~2 per page. Debts carousel dots at 8px are the worst (P2).
X6 P3 Subscriptions empty state: 3 catalogue `<img>` with no alt (Netflix, Shahid VIP, ...). Fix: alt="" if decorative or the service name.
X7 P3 Heading structure: /notifications has 2 h1 (title + ring "60%"?), /404 has 2 h1, legal pages have 2 h1; /start renders an h1 but no text. Expected one h1 per page.
X8 P3 Console, every page load (dev): "Encountered a script tag while rendering React component" at src/app/layout.tsx:137 (`<script nonce>` inside `<head>` of RootLayout). React 19 logs this as console.error on each load; scripts rendered by React on the client never execute. Fix: move the nonce script to a next/script or a raw string in the document head via the supported API.
X9 P3 Console: "[useAssetPrices] Error: Missing NEXT_PUBLIC_SUPABASE_URL" console.error loop from AppViewRouter in this no-Supabase mode (useAssetPrices.ts:147, supabase/client.ts requireSupabaseUrl throws inside refreshAssetPrices). In production env present, but the throw is caught only by a logger; for the bypass/QA config it floods the console and makes real errors hard to spot. Fix: skip the effect when not configured.
X10 P3 Network: /api/rates fires 8 times per page load (plus /api/gold, /api/ai x2, /api/auth/password-updated), several ending ERR_ABORTED on navigation. 154 /api requests buffered across ~12 page loads. In dev StrictMode doubles effects, but 4 distinct hook consumers each fetching suggests no shared in-flight dedupe. Fix: one shared rates query (SWR/react-query style) with in-flight sharing.
X11 P2 404 page (any locale): bare Next.js default "404 | This page could not be found." inside the app shell. English-only even with language=ar, no heading hierarchy, no link back to Flow, 2 h1. Expected: branded not-found with translated copy and a "Back to Flow" button.
X12 P2 /offline page: English-only under lang="ar", no retry button or links (0 interactive controls), no illustration/brand: dead end; also the document keeps lang="ar" while body is English (a11y/lang mismatch). Same for /legal/privacy|terms (English content, html lang="ar" when the user's language is Arabic).
X13 P3 /start renders a blank screen indefinitely in bypass mode (body text length 0 after 20 s; container has height 812, no skeleton). OnboardingRoute returns null until useOnboardingState().ready; if it never becomes ready there is no loading or fallback UI. Likely bypass-only, but worth a skeleton/redirect timeout.
X14 P3 Arabic layout is half mirrored although DESIGN_SYSTEM says "UI layout stays LTR, html dir always ltr": in Settings (ar) the row icons and toggles move to the right and the chevron to the left, while the page heading, section captions, top bar (title, filter and profile buttons) and the 5 quick-setting tiles keep LTR positions (the tile order is reversed: search first, EN/ع last). Mixed alignment looks inconsistent: heading flush left, rows flush right. Expected: one rule; either fully LTR or mirrored.
X15 P3 Add sheet (375): menu subtitles truncate ("A recurring ch...", "Card, bank, wa...") and the voice hint line at the bottom ("... + in the bottom bar to add by voice") is clipped on its left edge by the sheet content; last tile "Pay method" sits alone in a half-width row. Fix: allow 2-line subtitles or shorten copy; center orphan tile or add one.
X16 P3 First tap on the Quick add FAB by coordinate right after page load did nothing (ghost-click grace period 400ms per project notes; a second click via ref worked). Users tapping quickly after load can think the button is dead. Low confidence.
X17 P3 Theme: default stays "light" even when the OS reports prefers-color-scheme: dark (emulated dark; data-theme remained "light" until setting changed). Fine if intended; confirm "system" option exists.
X18 P3 Dark mode (375/768/1280): "One-time" chip text contrast 4.15:1 at 9.5px (needs 4.5:1); hidden swipe labels "Delete" 3.09:1 and "Link" 2.29:1 at 10px (low confidence: may be behind the row until swiped). Many labels at 9.5-10.5px (hero captions, chips) are under the 11px comfortable minimum.
X19 P3 Goals: seeded goal created via addGoal without a status (status null) is invisible in every tab (All/Active/Paused show "No goals here yet") and the "0 achieved" counter hides it. Data written by sync/import without status would vanish. Fix: treat missing status as active in the selector. (Seed artifact, but shows a silent-data-hide path.)
X20 P3 Debts (375): inline card "Plan a clear-by ... payoff goal" text is clipped against its button ("Plan a clear-by" cut mid-phrase). Also a they_owe debt appears under "Borrowed 2" with hero "Still owed 250,000" excluding it (the Ahmed seed lacked a direction field in the UI model; verify tab grouping for lent vs borrowed).

- /paydays, /budget-history, /offline: 0 controls under 44px.
- Settings switches: all 8 have aria-label + aria-labelledby; top tiles have aria-labels (Language, Theme, Currency, converter, search).
- Add-expense dialog: role=dialog aria-modal=true; Escape dismisses; category chips and amount field >=44px; Save disabled with the hint "Enter an amount to continue".
- Tablet 768 dark and desktop 1280 dark /flow: sidebar appears at desktop, no overflow, rows truncate the long description with an ellipsis.
- Dark mode flow at 375: surfaces consistent, hero unchanged (same green in both themes).
- Layout shift entries: 0 observed on /flow (PerformanceObserver only after load).
