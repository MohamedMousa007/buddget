# QA Round 2: I18N + FORMATTING (read-only discovery)

Method: TS-transpile key diff of en/ar dictionaries; TypeScript AST scans for JSX text / aria / placeholder / title / toast literals; ripgrep sweeps for Intl/toLocale/date-fns/physical CSS/letter-spacing; node evaluation of Intl behaviour. Scripts in scratchpad/qa2/tmp-i18n/. Design note (docs/DESIGN_SYSTEM.md:141-146): layout is deliberately LTR for Arabic (html dir always ltr), digits always Latin. Findings below respect that decision; the cost of it is reported as T11.

## Quantified results
- Dictionary parity en vs ar: 3021 leaf keys each, 0 missing, 0 extra, 0 placeholder mismatches, 387 function keys each. 13 identical en==ar (all intentional brand/code), 7 Latin-only ar (intentional). Key diff is CLEAN.
- Hard-coded English in UI (AST, excluding features/admin and app/legal): 170 hits; 14 of them covered by inline ar ternaries (WelcomeScreen, LandingGate, SettingsSearch), so ~156 real hits in 24 files with zero Arabic path. Excluded: features/admin 488 hits (staff only), legal 234 (English only).
- Per dir (real): components/voice 42, components/receipt 30, components/features/savings-v3 ~58 (ZakatSheet 19, PocketFormSheet 12, AssetFormSheet 7+20 prop strings), components/onboarding/sms 17, reports 5 (+ReportFilters 5 labels), app/error+global-error+offline 9, hooks 8 error strings, setup 3, ui aria 6.
- Inline en/ar ternary or COPY tables outside src/lib/i18n: 175 occurrences (parallel translation system, no type parity).
- date-fns format() with month/weekday tokens and no locale: 26 calls in 14 files.
- toLocale*/Intl calls with hard-coded en-US/en-GB (ignores app language): 26.
- Arabic function strings with count + plural noun lacking dual / 11+ forms: ~35 of 61 count fns; 13 English plural fns have no Arabic branch at all.
- Arabic strings ending in Latin "." : 352 (plus fn strings).
- letter-spacing/tracking utilities: 150 occurrences in 103 files, no Arabic reset. uppercase: 78 in 58 files.
- Physical CSS (left/right/ml/mr/pl/pr/text-left/right) outside admin/i18n: ~70 occurrences, mostly centred overlays / legal / charts; logical props already dominate (163 ms/me/ps/pe/start/end, 106 text-start/end). Low value given forced LTR.
- Hard-coded en-US locale in numeric format: formatters.ts numberLocale() by design.

## Findings

T1 P1 Crypto and gold quantities rounded to whole numbers; BTC amounts display as 0.00
- src/components/features/savings-v3/WealthList.tsx:47-50 uses formatWhole(h.quantity) for gold (g), crypto, stock units. 0.0123 BTC shows "0", 2.5 g gold shows "3 g". src/lib/utils/formatters.ts:70-75 formatCurrency uses 2 fixed decimals, so BTC 0.00012 renders "₿0.00" (verified in node). XAU is toFixed(2) with no grouping (formatters.ts:66, 97).
- Scenario: user adds 0.0123 BTC in AssetFormSheet; the row says "0 x price".
- Fix: unit-aware precision (crypto up to 8dp trimmed, gold 2-3dp) via a quantity formatter.

T2 P1 sanitizeAmount turns thousands separators into decimals and caps decimals at 2
- src/lib/ui/amountSanitize.ts:13 maps "," to "."; paste "1,250.50" gives "1.250.50" then "1.25"; "1,250" gives "1.25". MAX_DECIMALS=2 (line 5) blocks KWD/BHD/OMR/JOD/TND (3-dp currencies, all in currencyMeta.ts:11-17) and crypto/gold quantities.
- Scenario (web path, AmountTextInput): paste a bank amount with grouping, balance silently becomes 1.25.
- Fix: strip grouping commas when a "." exists / when comma followed by exactly 3 digits; per-currency decimals.

T3 P1 Whole user flows have no Arabic: voice capture, receipt scan, add-pocket, zakat, asset form, global error pages
- Zero Arabic markers and no useT: VoiceRecordSheet.tsx (21 hits, e.g. :311,:327,:345,:485,:515), VoiceRecordOverlay.tsx (11, :269,:286,:391), VoiceRecapEditor.tsx (10, :34-48 labels), ReceiptScanSheet.tsx (27, :155-160 errors,:294-342,:533), ReceiptDetailSheet.tsx (:46,:53,:77), PocketFormSheet.tsx (12, :86-175), AssetFormSheet.tsx (:26,:109-202), ZakatSheet.tsx (19, :87-90,:103-107,:129-226; also has t.* for part so mixed), error.tsx:24-30, global-error.tsx:27-33, offline/page.tsx:5-6, MonthlyChart.tsx:24-31,:61, CategoryPieChart.tsx:27-31, ReportFilters.tsx:13-17, IosSmsSetupClient.tsx:32-76, hooks useVoiceExpense.ts:218,:258,:364,:378,:404,:459, useSmsTracking.ts:166,:190.
- Scenario: Arabic user opens FAB > scan receipt / voice: every label, error, aria-label is English. Reports page chart titles and filter chips English.
- Fix: move to dictionaries; global-error/offline need a no-provider locale read.

T4 P2 Arabic plural forms wrong (no dual, no singular for 11+)
- ar.ts:912 sourcesCount ("1 مصدر" ok, "11 مصدر" ok, "2 مصدر" no dual), :1165 activeDebtsCount "1 ديون نشطة", :1408 fPaymentsCount "1 دفعات", "11 دفعات" (should be دفعة), :2658 statusBehind/bannerBehind/coachTitle ("متأخر 3 ربع"), :3177 offlinePending "1 رسائل", :413 stripDaysOld "1 أيام", :190 manyDidntSync, income.arrivedDaysLate n=2..10 ok but 11+ uses "أيام", subscriptions chips handle dual (the right pattern: ar.ts subscriptions.ui.chips.inDays).
- English side is 48 plural fns; 13 have no Arabic branch.
- Fix: shared arPlural(n, {one,two,few,many}) using Intl.PluralRules('ar').

T6 P2 Negative amounts: symbol before sign
- formatters.ts:74-82: formatCurrency(-5,'USD') = "$-5.00", (-0.004) = "-0.00" (verified). Math.round(-0.4) gives "-0" in formatWhole (:153). formatMoneyHero (:99-120) same. 
- Fix: format abs and prefix sign (formatSigned exists for some callers).

T7 P2 Arabic keyboard digits rejected or zeroed in amount/day/last-4 inputs
- AmountReceivedSheet.tsx:188 strips [^0-9.] (Arabic digits vanish, multiple dots allowed). \D strips: accountFormParts.tsx:50, AddLineSheet.tsx:124, StepIncome.tsx:135, PocketFormSheet.tsx:129, UnifiedDatePicker.tsx:328, AuthOtpRow.tsx:19,:27,:56, useAuthModal.ts:465. T8 P2 Week starts on Sunday; Egypt is Saturday-first

- Fix: weekStartsOn: 6 for ar/EG (or per user setting) in picker and preset.

T9 P2 Date picker year list capped at 2035 and keeps a parallel month/weekday table
- UnifiedDatePicker.tsx:19 YEARS 1970..2035; goals/debts/installments beyond 2035 (20-year loan, retirement goal) cannot be picked. MON_AR/WD_AR/WDL_AR duplicate date-fns arEG data (:14-18).
- Fix: derive upper bound from now + 50y.

T10 P2 Letter-spacing breaks Arabic joining
- 150 tracking-*/letter-spacing occurrences in 103 files (e.g. NumberPad.tsx:197 uppercase tracking-[.09em] caption) and no `html[data-locale='ar'] * {letter-spacing:0}` in globals.css:549-562. Tracking disconnects Arabic letters into isolated glyphs.
- Fix: one CSS reset for ar.
