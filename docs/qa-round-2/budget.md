# QA Round 2 - BUDGET + REPORTS (read-only; probe run under TZ=Africa/Cairo, deleted)

Legend: [P] = confirmed by a throwaway probe, [C] = confirmed by code reading.

## P1
R1 [P] Plan-line amount patch corrupts lines with subcategories / non-base rows.
 src/lib/budget/lineEdit.ts patchInBase + src/hooks/useBudgetPageActions.ts patchLine (used by MonthCloseSheet onApply BudgetPlanPage.tsx ~l.436, insight "raise" ~l.150, syncLive/syncAllLive) + store updatePlanCategory.
 Problem: patchInBase forces currency=base on any {amount} patch. effectivePlanCategoryAmount ignores `amount` when subcategories exist (sums subs).
 Scenario: USD row, subs 100+50 USD (= 7,536 EGP at 50). Close-sheet "Apply raise to 9000" -> amount 9000, currency EGP, subs unchanged: line now = 150 EGP (probe: before 7535.9, after 150). Sheet shows "Applied" ticks. Base-currency subcategory lines: patch silently ignored.
 Fix: patch subs proportionally (or collapse subs), convert untouched sub amounts, never flip currency without converting.
R2 [P] moveFreeToBuffer corrupts a non-base Buffer line. useBudgetPageActions.ts moveFreeToBuffer.
 Computes amount in the buffer's own currency (`cur`), then patchLine -> patchInBase stamps base currency. USD buffer 100 (5,024 EGP) + 1000 EGP free -> {amount:120,currency:EGP}; buffer drops 5,024 -> 120. Reachable after any base-currency switch (rows keep old currency).
 Fix: pass currency explicitly / skip patchInBase.
R3 [P] Deleting a recurring income source erases its realized history from every income figure. useFinanceStore.deleteIncomeSource (l.374) removes only the template; IncomeSheetForm.tsx:209, aiActionHandlers.ts:708 (Buddgy delete_income).
 actualIncomeForMonth (calculations.ts ~l.215) skips events with templateId and only counts events through live templates -> orphan confirmed events count 0 (probe: 5000 confirmed event, template gone -> 0). Hero totalIncome, leftToSpend, Reports "Total in/Net saved" drop to 0 for past months, while Flow ledger still lists the events (ledger Money in != stats income). Buddgy prompt even tells user to end-date instead.
 Fix: count orphan realized events as standalone, or cascade/confirm delete, or soft-end instead.
R4 [C] Reports page ignores monthStartDay and spend semantics. src/hooks/useReportsPage.ts.
 (a) Uses calendar months (startOfMonth, actualIncomeForMonth(..., 1)) so with start day 25 "This month" != hero cycle. (b) totalExpenses/"Total out"/"Net saved"/remittances/largest purchase/monthly chart use filteredExpenses with NO isNonSpendExpense filter: Savings allocations, ATM, Transfer, FX, CC Payoff, Top up, Installment are counted; "Biggest purchase" can be a 50k transfer. categoryData only drops 'Savings', so pie shows CC Payoff/Top up/Transfer slices. Payment-method panel DOES exclude non-spend, so its total != Total out. Hero "Money out" excludes them. Same month, three different spend numbers.
 Fix: reuse calculateTotalSpentExcludingSavings / isNonSpendExpense and getMonthRange(monthStartDay).
R5 [C] Two different "Left to spend" figures. Flow hero (useFlowBand: budget - spent) vs stats.leftToSpend (cash-flow: income - spend - savings - reserve) used by Buddgy get_summary (reports.ts:64, "left_to_spend" next to "safe_daily" which is budget-based), runAiCommand.ts:64, context.ts, AddSavingsSheetV3. Buddgy answers a different number than the hero labelled identically.
R6 [C] Month navigation allows a future cycle when monthStartDay > 1. FlowMonthRow.tsx: atCurrent = monthFilter >= format(new Date(),'yyyy-MM') (calendar). Start day 25, today Oct 10: current cycle key = 2026-09 (probe), calendar = 2026-10, so Next stays enabled and opens the not-yet-started 2026-10 cycle: daysLeft=whole span, pace projects spent*totalDays, widget/notifications key on it. Use cycleKeyFor(new Date(), startDay).
