# QA Round 6: time zones, calendars, locales, numerals, RTL (TZL)

Covered: grep + classification of every date-arithmetic pattern in src/ (toISOString slice 14 hits, `/86_400_000` 40 hits, getTime keys, addWeeks/addDays chains, `new Date(dateOnly)`, calendar-week helpers), server-vs-device date use (month-carry cron, notifications delivery window/wallClockNow, SMS `smsLocalDay`, matchSalary weekend), the six existing unit-suite groups (lib/utils, lib/time, lib/income, lib/savings, lib/budget, hooks: 100 files / 774 tests) under 7 TZ values, Arabic parsing/display, Arabic plurals, RTL class/chevron grep, hard-coded English, ad hoc `toLocaleString`. Not covered: live UI in RTL (no browser run), Hijri (no Hijri calendar exists in the app: zakat hawl is a 354-day offset, `hawl.ts`), EN/AR key parity beyond the existing `dictionaryParity.test.ts` (passes), full JSX-literal audit (sampled), chart axes.

- `wallClockNow` returns a Date whose local fields mimic the wall clock; wrong only if the server runtime is not UTC (Vercel is UTC), so not reported.
