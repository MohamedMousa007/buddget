# QA Round 6: native-notify (NAT)

Covered: Android Kotlin/manifest/res/xml (SmsReceiver, SmsForwardWorker, SmsStore, PendingSmsQueue, SmsGate, DocumentScannerPlugin, MainActivity, FileProvider paths), iOS Info.plist/entitlements/PrivacyInfo/AppDelegate/CatchBankSmsIntent, JS native layer (pushNotifications, pushActionQueue, deviceSecret, deviceId, smsTracker, signOut path), /api/notifications, /api/push/register, /api/push/send, cron/notifications, emitNotification, sendNativePush, pushMask. Not covered (yet): iOS SmsCapacitorPlugin.swift line-by-line, biometricAuth.ts, voiceRecorder, cameraScanner, backGuard registry, live pg_cron SQL (see updates below).

## Findings
| ID | P | file:line | finding | evidence | suggested fix | status |
|----|---|-----------|---------|----------|---------------|--------|
| NAT-1 | P2 | android/.../SmsReceiver.kt:~95, SmsForwardWorker.kt | Receiver enqueues `setExpedited(RUN_AS_NON_EXPEDITED_WORK_REQUEST)` for a `CoroutineWorker` that does not override `getForegroundInfo()`. minSdk is 24; on API 24-30 WorkManager runs expedited work as a foreground service and calls getForegroundInfo, whose CoroutineWorker default throws `IllegalStateException("Not implemented")`. Background forwarding then fails on Android 7-11 and the SMS waits in PendingSmsQueue until the app is opened (defeats the killed-app promise). | Read: worker has no getForegroundInfo override; variables.gradle minSdk 24; WorkManager 2.9.0. | Override getForegroundInfo (with a notification channel) or drop setExpedited. | Static |
| NAT-2 | P2 | src/components/auth/AuthProvider.tsx:465, SmsCapacitorPlugin.kt clearCredentials | Explicit sign-out intentionally keeps the non-expiring SMS ingest token, owner stamp and `sms_enabled=true` on the device. After the user signs out, bank SMS keep being forwarded to the signed-out account (and the token stays valid for an attacker with the device/backup) until another account signs in and reconcileSmsOwner runs. Logout does not clear every native store. | Code comment "clearSmsNative() intentionally NOT called"; receiver gate only checks sms_enabled. | On explicit sign-out call clearCredentials (keeps queue and wired state) and re-arm on SIGNED_IN (ensureIngestToken already does). | Static |
| NAT-3 | P2 | src/lib/native/deviceSecret.ts:9 | The Round 5 trusted-device secret (skips the email-code step) is stored in `@capacitor/preferences` (iOS UserDefaults, Android plain SharedPreferences), unlike the SMS token (Keychain / EncryptedSharedPreferences). iOS UserDefaults go into device backups; rooted/jailbroken reads it in clear. | Read: `Preferences.set({key:'buddget_device_secret'})`. Android data_extraction_rules exclude sharedpref, iOS has no equivalent exclusion. | Store in Keychain (ThisDeviceOnly) / EncryptedSharedPreferences via a small plugin or secure-storage plugin. | Static |
| NAT-4 | P3 | src/components/layout/AppShell.tsx:344-393, cron/notifications:153,208,225, cron/month-carry:162,205 | Every cron push carries `data.kind='notification'` (+notifType) but the tap handler only routes `sms_*` kinds. Tapping a debt-due / subscription / goal / month-carry push opens the app at the last screen with no deep link; `notifType` is never read. | `grep notifType src` shows only writers, no reader. | Map notifType to a route (debts, subscriptions, goals, savings) in the handler. | Confirmed (grep) |
| NAT-5 | P3 | src/lib/server/sendNativePush.ts:97-104, push/send/route.ts:34 | `messaging/invalid-argument` is treated as a dead token and the token row is deleted. A payload fault (collapseKey > 64 bytes becomes an invalid `apns-collapse-id`, reserved data keys such as `from`/`google.*`) therefore deletes ALL the user's tokens for that send. `/api/push/send` allows collapseKey up to 120 chars and arbitrary data keys (self-targeted only, so self-DoS of push until next app open re-registers). | Read only; cron slices collapseKey to 60. | Delete only on `registration-token-not-registered` / `invalid-registration-token`; cap collapseKey at 64. | Static |
| NAT-6 | P3 | sendNativePush.ts:92 | iOS payload hard-codes `badge: 1`; the badge never reflects unread count, and a grep of src found no badge clear/set call. | Read. | Send real unread count or omit badge. | Static |
| NAT-7 | P3 | src/app/api/notifications/route.ts:34 | `unreadCount` is computed from the 80 newest rows only, so it undercounts once more than 80 notifications exist (bell badge wrong). | Read. | `select count` with `.eq('is_read', false)` head query. | Static |
| NAT-8 | P3 | android/.../DocumentScannerPlugin.kt:onScanResult | Up to 5 scanned pages are read, decoded, rotated, re-encoded and base64'd on the main thread inside the ActivityResult callback: jank or ANR on low-end devices; a process death while the scanner is open loses the call silently. | Read. | Move to a background executor, resolve from there. | Static |
| NAT-9 | P3 | src/lib/server/emitNotification.ts:49-60 | The notification row is inserted first, the push second; if the push fails (Firebase down, no config) the dedupe key already exists, so no later cron run ever re-sends it. The in-app row exists, the OS push is lost for good. | Read: `created:true` returned even when sendNativePush returned `ok:false`. | Record push status, or retry rows with no push sent. | Static |
| NAT-10 | P3 | AndroidManifest.xml:30-35, Info.plist CFBundleURLTypes | Intent filter / URL scheme `app.buddget://auth/callback` is registered but no `appUrlOpen` listener exists anywhere in src (native OAuth is idToken-only). Dead entry point on an interceptable custom scheme; no autoVerify App Links or universal links (`applinks:`) exist at all. | `grep appUrlOpen src` = no matches. | Remove the filter and scheme, or add a handler that ignores unknown paths. | Confirmed (grep) |
| NAT-11 | P3 | src/lib/privacy/mask.ts:6, sendNativePush.ts | Default privacy preset `off` means pushes show amounts and merchants on the lock screen (up to 120 chars of body). Masking is opt-in. Product decision, flagged for the privacy review. | `isMasked(undefined,'notifications')` returns false. | Consider default-masked on first push permission or an onboarding choice. | Static |
| NAT-12 | P3 | vercel.json:7, pg_cron `notifications-hourly` (0 * * * *) | DBI-9 confirmed: both a Vercel daily cron (06:00 UTC) and the hourly pg_cron job call /api/cron/notifications; at 06:00 UTC two runs start in the same minute and both read/write `notification_cron_cursor`. No duplicate pushes (unique index `notifications_user_dedupe_uq` on (user_id,dedupe_key) makes the second insert 23505, `created:false`, no push), but the full per-user evaluation runs up to 12x/day and the Vercel run is redundant. | SQL: cron.job lists notifications-hourly active; pg_indexes shows the unique index. | Drop the Vercel entry. | Confirmed |
