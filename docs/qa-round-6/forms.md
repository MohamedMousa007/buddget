# QA Round 6: forms, sheets and inputs (FRM)

Covered: amount entry chain (amountParse/amountSanitize/AmountField/NumberPad), add and edit expense, add subscription, new goal, add debt / pay debt / installment, withdraw-from-savings submit, income sheet, budget add-line, household rent, ModalShell exit behaviour, a11y names of amount fields, and a call-site scan of every `AmountField`/`AmountTextInput` (about 60 sites). Hooks were driven for real (store + hook, no mocks of logic) with the Round 5 hand-written hook runner (`liteReact`) because the repo has no jsdom/testing-library; markup checked with `renderToStaticMarkup`. Not covered: live DOM interaction (no dev server), AR/EN error-message wording per form, native pad on device, payment-method / savings-account / budget-flow sheets beyond the call-site scan, offline submit (store writes are local-first, nothing form-specific found), keyboard-only sweep beyond code reading.

Repros: `docs/qa-round-6/repro/forms/*.txt` (rename to `.ts` under `src/__qa6__/forms/`; `liteReact.ts.txt` is the hook runner). Run in Cairo, New York and Riyadh: the same 12 pass / 15 fail pattern in all three (failures are the findings below, none are TZ dependent).
