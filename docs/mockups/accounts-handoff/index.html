Grouping rules (for the implementer)

  1. Group key = resolvePaymentBrandKey(accountTitle(m)), else the normalised name. Display name = the catalogue name.
  2. A card's group: its parent's group (parentId wins over its own name). If the parent is closed or missing, its own provider's group; if that provider is not identifiable (not in the catalogue and no open account with that provider) or is pay-later, Other cards.
  3. A prepaid_card holder with no parent belongs to its issuer's group, drawn as a face with "Prepaid". It is an account in useAccounts and counts once in the group total; it is never added again as a card.
  4. Group total = Σ tracked accounts in base currency (prepaid included once); credit owed never enters it.
  5. Section: a group is a wallet group when any of its accounts is a wallet (or, for card-only groups, the catalogue type is wallet); otherwise it is a bank group. Cash keeps its own row inside "Wallets and cash".
  6. standaloneCards needs !m.provisional: today a provisional method from SMS fails isOpenAccount and would fall into Other cards.

Tests (deep): alias grouping (NBE / National Bank of Egypt), prepaid counted once, credit excluded, closed-parent card falls back, unknown provider → Other, provisional excluded.

FX rate error report

What exists: there is no generic "errors queue" or "tech tickets" table. The closest mechanism is the admin Crashes queue: table client_crashes (supabase/migrations/0184_client_crashes.sql), written only through the service-role RPC record_client_crash(...), deduped by UNIQUE (fingerprint, release) with an occurrences counter and a new → acknowledged → resolved status (a resolved row reopens on a new hit). Admins see it in src/components/features/admin/views/CrashesView.tsx via src/app/api/admin/crashes/route.ts. Today only the Sentry webhook writes it (src/app/api/webhooks/sentry/route.ts). User support tickets (src/app/api/support/*) are user-facing and not the right place.

Where to report: in src/app/api/rates/route.ts GET, after validRates: when all providers fail (the existing 502 branch), and for each currency in CURRENCIES that is missing from the merged result. Use createServiceRoleClient() from src/lib/supabase/service, fire-and-forget (never block or fail the response).
