Grouping rules (for the implementer)
Group key = resolvePaymentBrandKey(accountTitle(m)), else the normalised name. Display name = the catalogue name.
A card's group: its parent's group (parentId wins over its own name). If the parent is closed or missing, its own provider's group; if that provider is not identifiable (not in the catalogue and no open account with that provider) or is pay-later, Other cards.
A prepaid_card holder with no parent belongs to its issuer's group, drawn as a face with "Prepaid". It is an account in useAccounts and counts once in the group total; it is never added again as a card.
Group total = Σ tracked accounts in base currency (prepaid included once); credit owed never enters it.
Section: a group is a wallet group when any of its accounts is a wallet (or, for card-only groups, the catalogue type is wallet); otherwise it is a bank group. Cash keeps its own row inside "Wallets and cash".
standaloneCards needs !m.provisional: today a provisional method from SMS fails isOpenAccount and would fall into Other cards.

Tests (deep): alias grouping (NBE / National Bank of Egypt), prepaid counted once, credit excluded, closed-parent card falls back, unknown provider → Other, provisional excluded.

FX rate error report

What exists: there is no generic "errors queue" or "tech tickets" table. The closest mechanism is the admin Crashes queue: table client_crashes (supabase/migrations/0184_client_crashes.sql), written only through the service-role RPC record_client_crash(...), deduped by UNIQUE (fingerprint, release) with an occurrences counter and a new → acknowledged → resolved status (a resolved row reopens on a new hit). Admins see it in src/components/features/admin/views/CrashesView.tsx via src/app/api/admin/crashes/route.ts. Today only the Sentry webhook writes it (src/app/api/webhooks/sentry/route.ts). User support tickets (src/app/api/support/*) are user-facing and not the right place.

Where to report: in src/app/api/rates/route.ts GET, after validRates: when all providers fail (the existing 502 branch), and for each currency in CURRENCIES that is missing from the merged result. Use createServiceRoleClient() from src/lib/supabase/service, fire-and-forget (never block or fail the response).

RPC ARGUMENT	VALUE
p_fingerprint	fx_rate_missing:<CUR>:<YYYY-MM-DD UTC> (all providers down: fx_rate_missing:ALL:<date>). This is the dedupe: one row per currency per day; repeats only bump occurrences.
p_release	'' (server, not a client release)
p_title	FX rate missing: USD
p_level	'warning' ('error' when all providers fail)
p_culprit	api/rates + the provider tried last (providerUsed)
p_stack	Short list of providers tried and their failure (no user data)
p_platform	'server'
p_build, p_device_id, p_user_id, p_sentry_issue_id, p_sentry_url	null
p_seen	new Date().toISOString()

No migration needed (level already allows warning; the 120-day retention job already covers the table). The client keeps showing the dismissable rate alert from useRates when a needed currency has no rate. Test: route test that two failing calls on one day produce one RPC fingerprint, and that a success path never calls it.

Which skill informed which decision
SKILL	DECISIONS
artifact-design	Page contract, theme tokens (the provider tint uses --ph-amt / --ph-base tokens per theme), 16px gutter, frame-contained sheets.
ui-ux-pro-max	44px targets, predictable back, semantic colour (red for negative, amber for gaps) separate from the brand tint.
design:design-critique	Provider hero cut to three facts; empty activity kept visible so the sheet's shape does not jump.
ecc:make-interfaces-feel-better	Tabular numbers, dimmed decimals, press scale, explicit transition properties, skeleton matching row geometry.
design:ux-copy	Rate alert says what failed and what it means; "Available" over "Remaining"; "Add an expense" as the one action; "± Overdrawn (minus)" names the outcome; Arabic strings reuse existing dictionary terms (مستحق، مُخصَّص).
design:accessibility-review	Hero tint contrast computed per brand (table above); banner uses role="alert" with a labelled dismiss; ± key is aria-pressed; skeleton has aria-busy; folded stack faces aria-hidden.
ecc:frontend-design-direction	Modern via the brand-tinted provider hero and a 2×2 credit grid, not new chrome; content states (loading, empty, error, partial FX) recorded above.
ecc:motion-patterns	Sheets 280ms in / 180ms out; shared-axis push; stack spread transform-only; skeleton shimmer off under reduced motion.
