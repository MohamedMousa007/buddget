BDG-020 Subscription: every screen, built from existing components

Phone-sized screens using only parts that exist in the app, with the app's real wording. New strings are marked NEW. No new component is introduced. The Manage bar, Receipts, Billing history, the "How to cancel" row and the standalone Restore are removed from the page; "Problem with a purchase?" survives only as a "?" icon in the cancel sheet's header.

What gets built, and from what

PieceExisting part reused
Change plan row, Cancel rowSettingsSection, SettingsRow (destructive already exists), as the page already uses them
Cancel sheetModalShell, V3SheetHeader, SheetBody, the same ones the Manage sheet uses today
Retention offer, store hand-offThe stay card already in ProStateView.tsx, moved into the sheet; "Stay with Pro" is the primary Button, "Cancel anyway" a ghost Button in the red token colour (no new variant). The "?" is an IconButton in V3SheetHeader.Extra, used the same way in the goal and expense sheets. The steps card and its three-step copy are removed.
Payment issuePromptBanner and the state.issue copy, unchanged
Plans, RestorePlansBlock, BuyLine, StoreLinks, unchanged
New textThree NEW strings, English and Arabic: "Cancel subscription", "Cancel in store", and one line "You finish cancelling in {store}. You keep Pro until {date}." Everything else is an existing key.
Removed from the pageManageBar use, the Manage sheet rows, the Receipts sheet, the history list and its "See all". ManageBar itself stays in the membership gallery. BillingHistory is left in place for other pages.
Not introducedNo new component, no new variant, no custom colours: the red row uses the existing destructive token.
