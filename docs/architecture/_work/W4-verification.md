## Missed or worth adding

1. `sync_pull_v2` is VOLATILE and does `sms_run_my_pending_discards()` on every pull (`0300:109-130`): a second read-that-writes on the hottest path, not named in the report.
2. `loyalty_refresh_tier` takes `FOR UPDATE` on `loyalty_accounts` each time `entitlements_state` runs; that is the likely lock source behind the 41 s max (still NOT VERIFIED).
3. `/me` upkeep is also a functional dependency: `promo_apply_banked` must run before plan resolution, and 0332 makes app-open the retry for `awaiting_native` referrals. Any F-01 fix needs a test for both.
4. Admin sign-in `allowAttempt` fails closed on RPC error (`credentials.ts:50-55`): with `admin_rate_hit` tails up to 26 s (F-18), a DB stall locks staff out of sign-in. Mention under F-02/F-07.
5. Admin plan and flag write routes do not invalidate the platform cache today; the F-03 fix must add that, otherwise a kill-switch flag can lag 5 minutes.
6. Staff lock message leaks account existence (see F-07).
