# W5 diff review (correctness only)

## Findings
- risk | src/app/api/receipt/scan/route.ts:~269 | `await Promise.all(images.map(img => img.arrayBuffer()))` is outside any try, after the quota is reserved. If it throws (aborted upload, OOM), the reservation is never released. Fix: wrap the buffers/sniff block in try/catch that calls `rejected('Invalid form data', 400)`, or release in a catch-all around everything between reserve and settle.
- risk | supabase/migrations/0352_perf_audit_phase_a.sql:~58 | `VALIDATE CONSTRAINT profiles_avatar_image_path_len` fails the whole file if any live row has avatar_image_path > 300000 chars (old validator allowed 8 MB). Fix: run `SELECT count(*) FROM profiles WHERE length(avatar_image_path) > 300000` first; if > 0, trim/null them in the migration before VALIDATE.
- risk | src/lib/server/publicApiRateLimit.ts:~58 (memoryGateOk) | The blocked request is still pushed into the key's array, so one key flooding inside a window grows its array without bound until the window passes (the sweep only runs when the map has more than MAX_TRACKED_IPS keys, and per-key arrays are only trimmed on that key's next hit). Also `clientIp` = 'unknown' puts all unresolvable clients in one bucket (prices-refresh 6/min, site-event, site-lead). Fix: only push when `recent.length < maxHits` (return false otherwise); consider skipping the gate when ip === 'unknown'.
- risk | src/app/api/prices/refresh/route.ts:~29 | gate key uses raw `clientIp` (not `rateBucketIp`), so an IPv6 client rotating inside its /64 bypasses the per-isolate gate (check-email does bucket). Fix: use `rateBucketIp(clientIp(request))`, same for site-event/site-lead.
- nit | src/components/sync/SupabaseFinanceSync.ts:~120 | `DELTA_RETRY_MS[2]` (30_000) is never used: the check `deltaFailures >= length - 1` gives two retries (2 s, 8 s), then the full pull on the 3rd failure. Matches "fallback after 3 failures" but the third entry is dead; trim the array to two entries or compare to `length`. Counter is module-global and not reset on unmount/user change (cancelDeltaRetry only clears the timer); reset `deltaFailures = 0` there.
- nit | src/lib/server/admin/timeIdCursor.ts + admin/sms/logs, emails/log | An old client holding a pre-deploy plain-timestamp cursor now parses to null and is served page 1 again (Load older appears to repeat). A null `received_at`/`created_at` on the last row would format as `null|id` and loop the same way. Low impact; acceptable if both columns are NOT NULL.
- nit | src/lib/receipt/sniffImageMime.ts:~10 | HEIF brand allow-list omits heim/heis/hevm/hevs/msf1; those images now 415 where the declared type used to pass. iPhone photos are heic/mif1 so fine in practice.
- nit | src/lib/server/sendNativePush.ts:~40 | user_devices and user_settings are now fetched in parallel even when `rows` is empty or the token read errored (early return follows). Extra reads on the no-token path, not a bug.

## Cleared (no bug found)
- SupabaseFinanceSync delta retry: no bug found. Single timer (guarded by `if (deltaRetryTimer) return`), cleared on suspend and on effect cleanup, callback re-checks `syncSuspended`, retry goes through `syncFinanceNow` -> `pendingSync` which already coalesces via `reconciling`/`runAgain` (no concurrent pulls). Cursor is left untouched on a deferred failure, so the next pull reuses it; cold start (`since` null) never records a failure and falls to the full pull as before; stale() check precedes the counter.
- remote/sync.ts chunking: no bug found. Bisection/parking live inside `write(part)` so semantics are per chunk; ordering within a table preserved; `writes`/`skipped`/`adopted`/`parked` accumulate per chunk. Behaviour change only: a non-row error now fails one chunk while other chunks still write (errors still reported, flush not acked, upserts idempotent).
- receipt/scan quota: no bug found beyond the arrayBuffer note above. Reserve happens before formData(); `rejected()` releases on formData failure, no/too many images, bad MIME, size, bad sniff; settle path unchanged; sniffed MIME is what is sent to Gemini; the reserve estimate is approximate but settle uses real usage.
- entitlements/server.ts + flags route + cachedSetting: no bug found. Both readers `throw` on error (not cached); loadEntitlements maps a plans failure to the old `failed` flag; flags route returns `[]` on failure (same effective result as before, silently; consider a console.warn). All writers of plans/feature_flags are the admin routes, and each now calls invalidatePlatformSettings.
- admin/users/[id] audit-before-action: no bug found. `log()` returns the audit boolean; refuse path returns 500 before the wipe/delete; the post-action row is separate, so no double-act.
- admin/metrics.ts after(): no bug found. Only callers are the admin analytics and overview route handlers (valid request context); missing/over-45-min keys still wait or compute live; stale 15-45 min served immediately.
- timeIdCursor + sms/logs + emails/log: no bug found. Filter `col.lt.ts,and(col.eq.ts,id.lt.id)` is correct for (col desc, id desc); ids are validated uuids, timestamps regex-validated (no commas/parens injectable); a second `.or()` (errors queue) ANDs with it; `id` is in both selects; supabase-js encodes `+`; EmailLog sends via URLSearchParams.
- useNotifications: no bug found. sharedFetch throws on non-ok (not cached), effect depends on userId only, mark-read refetch uses ttl 0, `refetchServerNotifications` wrapped so no event is passed as `fresh`.
- publicApiRateLimit/memoryGateOk callers: behaviour when blocked is 429 + Retry-After; check-email sleeps to its deadline first (timing parity). Map growth see risk above.
- AuthProvider welcome backoff: no bug found. Parse of '' yields [0]; NaN becomes 0; all reads inside try; write failures land in the existing `.catch`. (A thrown fetch still records nothing, as before.)
- 0352 loyalty_refresh_tier: no bug found. Fast path returns only when tier and gifted rank are unchanged (null tier handled by IS NOT DISTINCT FROM); any change re-reads FOR UPDATE and recomputes, so the Sparks gift cannot double (READ COMMITTED re-reads the locked row). admin_user_directory: old signature dropped, new one grants service_role only, p_with_total default keeps old callers; UsersView still gets a total.
