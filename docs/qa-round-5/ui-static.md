## EN vs AR structural diff (clean)
`dictionaries/en.ts` vs `ar.ts`: 3447 leaves each; 0 missing either way, 0 type mismatches, 0 empty Arabic values, 0 `{placeholder}` mismatches. Function leaves return non-empty strings for sample args in both languages; only odd case `debts.goalSummary` yields "undefined" for an out-of-union frequency, but it is typed to 4 values (DebtCard passes `vm.goal.cadence`), so not a defect. The 17 paired copy modules (onboarding, voice, receipt, savingsForms, settingsHub, subscriptions, budgetPage/*, flowCopy 379 pairs, studio 482 pairs, etc.): same result, 0 structural issues, 0 arity mismatches. Only empty value is `budgetBlocks.actions.none` (`''` in both languages, intentional). Identical-to-English values are proper nouns/codes only and not reported. `dictionaryParity.test.ts` and `a11yLiterals.test.ts` already guard much of this.
